## 1. What exactly is our candidate contribution?

An offline, finite-budget *validation and selection* layer for **composition-level performance-prediction methods**. Given the same publicly disclosed provider-level evidence (I1), alternative reconstruction/composition estimators yield compliance predictions. Their errors are evaluated in heterogeneous **provider-world × composition-graph** conditions. The budget controller adaptively chooses which **predictor-condition error** to observe, and then recommends **one predictor for the specified whole evaluation domain**, minimizing estimated domain-mean error.

The current implementation is an archived **7 predictors × 12 physical conditions** replay with a common posterior final decision, not a live orchestration deployment, not per-SLA model routing, and not a selector across I1/I2a/I2b information-interface types. The seven candidates all use **public I1**. Full white-box references serve evaluation and retrospective scoring only. Original four-policy, supplementary one-step KG and new two-stage condition-selection studies are distinct, appropriately labeled evidence sets.

## 4. Specific novelty argument and its falsifiers

### Supported **candidate** contribution statement

> We design and evaluate a **budget-aware validation and method-selection layer** for composition-level service compliance prediction in the computing continuum. A shared public-I1 disclosure supports seven alternative graph-prediction method variants. Rather than assuming a fixed predictor, our layer sequentially acquires a limited set of predictor×provider-world×composition-graph validation errors and recommends a predictor for the target evaluation domain. Its offline evidence evaluates the final selection decision under fixed observation budgets and quantifies the contribution of adaptive condition choice.

This is **systems composition/integration plus reproducible empirical decision methodology**, not an assertion that KG, best-arm identification, prediction portfolios or active test selection were newly invented.

### What we cannot claim

- First system to select an algorithm for computing-continuum service composition (contradicted by Pozas García 2023).
- First active model evaluation/selection (contradicted by Hara 2024 and Kossen 2021).
- First cloud QoS prediction ensemble or model comparison (Mao 2024, Guerron 2026).
- New probabilistic SLA-composition rule (prior graph/SLA optimization exists).
- Online autonomic service selection, runtime model switching, deployed system with measured time savings, or per-graph model routing (not implemented/evaluated in B1).
- Selection across I1/I2a/I2b or comparison of provider disclosure interfaces (not in the seven-B1 portfolio).
- Statistically verified new-world generalization or confirmed runtime-cost savings (not demonstrated).

### Two reviewer counterfactuals to answer

1. **“Isn't this just Hara active model selection on another dataset?”** Answer must be concrete: in PRAISE the evaluation action incurs **per-method×physical-composition-condition** work and returns an aggregate stochastic-simulation reference error; method execution itself uses provider disclosure and graph mechanics. Stronger validation should demonstrate why this acquisition and cost structure changes practical design choices. If costs remain abstract, the paper should explicitly concede that the selection layer adopts established active evaluation ideas in a new service-composition domain.
2. **“Didn't Pozas García already select algorithms for compositions?”** Yes: it selects which **composition solver** to use from an empirical decision tree, while PRAISE selects which **composition compliance predictor** to trust using sequential validation actions. The difference of decision objects and evidence-collection workflow must be evident in Figure 1, methods and evaluation.

## 6. Workshop vs applied-conference threshold

**Workshop: CONDITIONAL GO for drafting.** Aim for an accurate 6–8 page systems-methodology contribution: clear problem and abstraction, architecture distinguishing public evidence from retrospective oracle, seven real I1 predictor variants, finite-budget acquisition, meaningful regret curves with paired uncertainty, and an explicit worked episode plus reproducibility. Include Pozas García, Stupar/Huljenic, Hara and at least one predictive QoS ensemble/comparison reference, not a 30-paper generic bibliography.

**Full applied conference: EVIDENCE GAP.** Stronger case would add independent provider-world results, actual marginal/total compute cost comparisons, and a more cohesive implemented workflow/API. The relative novelty of merely adapting KG remains low, but systems contribution can become substantial with convincing scope and operational relevance.

**Practical caution:** An offline archived validation experiment can support an honest *systems methodology* workshop paper, but do not claim to have already demonstrated a live end-to-end autonomic controller. The architectural figure must distinguish upstream simulation generation, blinded predictions, offline replay, reference-only evaluator, and unimplemented downstream consumer.
